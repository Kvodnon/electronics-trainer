# 11: Экспорт, импорт и сброс Прогресса

**What to build:** Управление данными: кнопка экспорта выгружает Прогресс и схемы Песочницы в JSON-файл; импорт восстанавливает их (например, в другом браузере или после переустановки системы); «начать заново» сбрасывает весь Прогресс после подтверждения. Некорректный файл импорта не ломает текущий Прогресс и объясняет, что не так.

**Blocked by:** 03 (Прогресс, который экспортируем)

**Status:** done

- [x] Экспорт скачивает файл со всем Прогрессом и схемами Песочницы
- [x] Импорт из файла, выгруженного этим же приложением, полностью восстанавливает состояние
- [x] Импорт битого/чужого файла отклоняется с понятной ошибкой, текущий Прогресс не повреждается (тест)
- [x] «Начать заново» очищает всё только после явного подтверждения
- [x] Тесты валидации формата; компонентный тест кнопок экспорта/импорта

## Comments

Implemented in feat commit (TDD: домен → хранилище/передача → UI → App; правки по code-review вошли в тот же коммит; 280 тестов, было 253) + ручная проверка в браузере. Layout:

- `src/domain/backup.ts` — формат файла: `{ kind: 'electronics-trainer-backup', version: 1, progress, sandboxCircuits }`. `serializeBackup` пишет снимок; `parseBackup(raw)` читает и целиком отклоняет битый или чужой файл (`{ ok: true, data } | { ok: false, error }`), объяснение называет проблему: не JSON / не файл Тренажёра / другая версия / повреждён Прогресс / повреждена схема Песочницы «Имя» (или №N, если имени нет). Частичное принятие не делалось — оно спрятало бы потерю данных. Сюда же переехали проверки формы данных (`isCourseProgress`, `isSavedCircuit`, `isCanvasState`) из обоих storage-файлов: localStorage-чтение и импорт файла проверяют одни и те же структуры, и домен остаётся чистым (строки без DOM). Прогресс без `failedOnce` (записан до статы «с первой попытки») читается с пустой статой — та же терпимость, что у localStorage.
- `src/domain/course.ts` — действия редьюсера `progress-reset` (возвращает `emptyProgress`; схемы Песочницы редьюсер не касается) и `progress-restored` (замена Прогресса снимком из файла целиком).
- `src/storage/fileTransfer.ts` — браузерная передача: `downloadTextFile` (Blob + скрытая ссылка) и `readTextFile` (FileReader). Слой побочных эффектов, домен чист. Адрес blob освобождается отложенно (`setTimeout 0`): мгновенный revoke может отменить ещё не начавшуюся загрузку — нашлось в code-review.
- `src/components/DataControls.tsx` — раздел «Данные» главного меню (в `App` рядом с `CourseScreen`): экспорт, импорт (скрытый `input type=file` по кнопке), «Начать заново» с двухшаговым подтверждением («Удалить весь Прогресс? Схемы Песочницы останутся.» → «Да, начать заново»/«Отмена»). Битый файл — `role="alert"` с объяснением из `parseBackup`; удачный — `role="status"` «Прогресс и схемы Песочницы восстановлены.»; нечитаемый файл (сбой FileReader) ловится try/catch и тоже объясняется. В `src/testing/fileDownload.ts` — общие тестовые подмены скачивания (`stubDownload`, `readBlobText`).
- CSS: панель раздела, скрытое поле файла, сообщения ok/error (`--correct`/`--incorrect`), строка подтверждения сброса.

Тесты (280): домен — roundtrip `serialize→parse` без потерь; метка и версия в файле; отказ для мусора/чужого JSON/чужой метки/чужой версии/битого Прогресса/отсутствующего списка схем/битой схемы (по имени и по номеру); терпимость к Прогрессу без `failedOnce`. Редьюсер — сброс в пустой Прогресс; импорт заменяет целиком. Хранилище — прежние тесты green на переезжавших проверках; fileTransfer — имя и содержимое скачивания, отложенный revoke, чтение файла. Компонентные (`DataControls`) — экспорт вызывает `onExport`; файл приложения вызывает `onImport` с проверенными данными и статусом; битый и нечитаемый файлы — alert без импорта; ошибка убирается удачным импортом; сброс только после подтверждения, «Отмена» ничего не делает. App — экспорт скачивает файл с текущими Прогрессом и схемами; экспорт → очистка хранилища («переустановка») → импорт восстанавливает Прогресс и схемы и переживает перезагрузку; битый и чужой файлы отклоняются, текущие данные на месте; «Начать заново» стирает Прогресс после подтверждения, схема Песочницы выживает, пустой Прогресс переживает перезагрузку.

Code-review (Standards + Spec): исправлено — «Сохранения…статы» в комментарии (запрещённое слово из Avoid-списка + жаргон), мгновенный `revokeObjectURL` после клика (в браузере может отменить скачивание; тест теперь проверяет отложенность), нечитаемый файл падал в необработанном отклонении без объяснения, дублирование `readBlobText`/подмен скачивания вынесено в `src/testing/fileDownload.ts`, комментарий про имя поля `sandboxCircuits` в файле. Оставлено осознанно: `domain/backup.ts` — дом проверки формы данных для двух потребителей (localStorage и файл); отказ файла целиком вместо частичного принятия.

Spec-решения, требующие подтверждения: (1) «Начать заново» стирает только Прогресс (taskStates + failedOnce), схемы Песочницы остаются — по формулировке тикета («сбрасывает весь Прогресс») и истории 42 («пройти Курс повторно»); текст подтверждения называет это явно. (2) Импорт заменяет обе области целиком (Прогресс и список схем), а не сливает — файл является полным снимком. (3) Стандарт обозначений (ГОСТ/ANSI) в файл не входит: это настройка интерфейса, не Прогресс.

Проверено вручную в браузере (IAB, vite preview): экспорт вызывает настоящую загрузку файла; «переустановка» (очистка localStorage) → подача файла в настоящий input → «Прогресс и схемы Песочницы восстановлены», Прогресс и «Кольцо» на месте и переживают перезагрузку; «Начать заново» — отмена ничего не делает, подтверждение обнуляет Прогресс, схема остаётся. Автоматизация выбора файла в диалоге ОС недоступна в панели IAB — путь файла до input проверен подачей DataTransfer, сам ввод покрыт компонентными тестами.
