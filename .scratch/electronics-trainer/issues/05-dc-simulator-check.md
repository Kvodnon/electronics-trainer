# 05: Симулятор DC и кнопка «Проверить»

**What to build:** Настоящая проверка Схема-заданий: аналоговый Симулятор на модифицированном методе узловых потенциалов (ADR-0001) для постоянного тока с поведенческими моделями М1 (батарея, резистор, лампочка, выключатель/ключ, моторчик). Условия Задания — декларативные диапазоны измерений; по нажатию «Проверить» ученик получает вердикт «пройдено/не пройдено» с Разбором, построенным на вычисленных токах и напряжениях. Эквивалентные схемы засчитываются: проверка по физике, а не по совпадению с эталоном.

**Blocked by:** 04 (Холст, из которого берётся собранная схема)

**Status:** done

- [x] Golden-тесты решателя: делитель напряжения, последовательное и параллельное соединение, короткое замыкание источника, обрыв (ток ≈ 0) — сравнение с аналитикой с допуском
- [x] Выключатель и ключ меняют решение схемы
- [x] Условия-измерения проверяются по решению: два разных по топологии решения одного Задания оба проходят (тест)
- [x] Кнопка «Проверить» показывает вердикт и Разбор на основе расчёта
- [x] Компонентный тест: собрать простейшую цепь → «Проверить» → «пройдено»

## Comments

Implemented in commit feat: DC simulator... (TDD: golden-тесты решателя → решатель, затем проверки условий → шов `evaluate`, затем UI). Layout:

- `src/domain/simulator.ts` — Симулятор DC, чистый TypeScript без DOM. Модифицированный метод узловых потенциалов: Провода объединяют выводы в узлы (union-find), каждый Компонент — ветвь между узлами выводов; острова без батареи не решаются (токи 0), остров с батареей решается узловыми уравнениями (Гаусс с выбором ведущего элемента), «земля» — минусовой вывод первой батареи острова. Поведенческие модели: батарея — ЭДС с внутренним сопротивлением 0,1 Ом (эквивалент Нортона: короткое замыкание даёт конечный ток ЭДС/r = 90 А, а не сингулярную матрицу); резистор/лампочка/моторчик — линейные резистивные; выключатель/ключ — замкнут 1 мОм / разомкнут 1 ГОм (обрыв честно даёт ток ≈ 0). Пороги активности: лампочка горит при P ≥ 20 мВт, моторчик крутится при P ≥ 50 мВт. Токи/мощности ниже 1e-7 — числовая пыль разомкнутых контактов, приводятся к нулю. Знаки: напряжение = вывод0 − вывод1 (у батареи — на зажимах), ток батареи — из «плюса» во внешнюю цепь, остальных — от вывода 0 к выводу 1.
- `src/domain/task.ts` — `CircuitCondition`: `component-used` (структурное, штук с min/max), `current-through`/`voltage-across`/`power-of` (диапазоны измерений, А/В/Вт), `component-active` (лампочка горит / моторчик крутится). Семантика измерений M1: условие выполнено, если границам отвечает хотя бы один Компонент вида; у симметричных Компонентов М1 знак тока/напряжения — артефакт ориентации символа, проверяется модуль. `CircuitTask.conditions` — обязательное поле.
- `src/domain/circuitConditions.ts` — проверка условий по решению: каждая возвращает `ConditionCheck {condition, passed, text}`; text — строка Разбора с измеренными числами и границами («Ток через лампочку — 74,9 мА, в границах условия (50–100 мА)»); при провале показания нет — берётся ближайшее к границам. Русская лексика видов (падежи) — `COMPONENT_LEXIS`.
- `src/domain/evaluate.ts` — `CircuitAnswer {canvas}` и `CircuitTaskEvaluation {outcome, conditionChecks, solution}`: solveDc + checkConditions, вердикт correct ⇔ все условия выполнены. Вердикт несёт решение — по ADR-0001 один движок питает и проверку, и показ токов ученику (оверлей — тикет 06).
- `src/domain/quantity.ts` — `formatQuantityRange` (общая приставка по верхней границе); добавлены единица «Вт» и приставка «мк» (форматирование и парсинг симметричны: мкА/мкВ читаются тоже).
- UI: состояние Холста поднято из `CanvasEditor` в `CircuitTaskScreen` (редактор стал управляемым: `history`/`onAction` + слот `actions` в панели редактора). «Проверить» снимок схемы отдаёт ответом `onAnswer` → ModuleScreen считает `evaluate` и возвращает вердикт пропсом (обвязка как у Вопросов). Вердикт «Пройдено/Не пройдено» + строки условий с ✓/✗; после правки схемы устаревший вердикт снимается (снимок сравнивается с текущим состоянием). Кнопка «Дальше» только при «Пройдено» → Задание закрывается в Прогрессе.
- `src/content/m2.ts` — витрина `m2-canvas-demo` получила настоящие условия (батарея, выключатель, лампочка, лампочка горит) и новый текст условия; М2 теперь завершается, Курс проходим целиком. Полный контент М1/М2 — тикеты 12/13.
- Тесты (147 всего, было 110): 15 golden-решателя (простая цепь, делитель, параллель, КЗ источника, обрыв, батарея без Проводов, коммутация выключателем и ключом, пороги лампочки/мотора, вырожденные схемы: остров без источника, замкнутый резистор, Провод на несуществующий Компонент, направления), 12 условий (структурные, измерения в/вне границ, отсутствие вида, любой из вида, зеркальное подключение, активные состояния), 5 шва evaluate (включая эквивалентные схемы: один 1 кОм против двух 500 Ом последовательно — оба проходят; пустой Холст проваливает), 15 компонентных (простейшая цепь → «Проверить» → «Пройдено» с Разбором по расчёту; разорванная → «Не пройдено» → правка снимает вердикт → «Пройдено»; витрина М2 из настоящего контента), 1 сквозной в App (М1 → М2 → Схема-задание → «Модуль пройден»).

Code-review (два агента: Standards + Spec): нарушений документированных стандартов нет; исправлено по замечаниям — `checkMeasurement` принимает исходное условие вместо пересборки через `as`-каст, параллельные switch'и сведены в карты `MEASUREMENT_TRAITS`/`ACTIVE_TRAITS`, два самодельных union-find в решателе заменены одним `DisjointSet`, выбор приставки в `formatQuantity`/`formatQuantityRange` вынесен в `prefixStepOf`, опечатка в JSDoc. Оставлено осознанно: `ConditionCheck.condition` и `CircuitTaskEvaluation.solution` (контекст вердикта и данные для оверлея тикета 06); семантика «хотя бы один Компонент вида» и `component-used` по факту постановки (не подключения) — требования подключения приносит классификатор Диагнозов (тикет 06), семантика «каждый из вида» — с контентом М2+, если Задания попросят.

Разметка панели инструментов с кнопкой «Проверить» сверена по скриншоту. Замечания среды IAB (те же, что в 03/04): отложенные коммиты при программных сериях кликов (жесты выполнялись по одному, состояние — по DOM), артефакты захвата скриншотов.

Заметки для следующих тикетов:

- Тикет 06 (Диагнозы и оверлей): решение уже в вердикте (`CircuitTaskEvaluation.solution.readings[]` — ток/напряжение/мощность на каждый Компонент); классификатор («короткое замыкание» — ток батареи ≈ ЭДС/r, «обрыв» — мощность нагрузки 0 при ненулевой ЭДС) ложится на эти показания; КЗ определяется по току батареи > 1 А (порог содержательный, М1-номиналы дают ≤ 0,2 А). Живое поведение: яркость от `reading.power`, пороги `LAMP_LIT_POWER`/`MOTOR_SPIN_POWER` экспортированы.
- Тикет 08 (Мультиметр): узловые потенциалы сейчас не экспортируются из `solveDc` (только ветви) — для щупов «напряжение между точками» достаточно ветвевых напряжений, для общих точек можно экспортировать и `nodeVoltage`.
- М2 (диод/светодиод — тикет 13): кусочно-линейная модель добавляется ветвью с итерациями или диод-моделью в `branchResistance`/`readingOfBranch`; условиям может понадобиться знаковая семантика тока — сейчас модуль закрыт в `checkMeasurement`, понадобится флаг в условии.
