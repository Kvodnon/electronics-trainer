# 02: Числовые Вопросы

**What to build:** Второй тип Вопроса — числовой ввод («посчитай ток»). Ученик вводит ответ с запятой или точкой, с суффиксами единиц (мА, А, кОм, МОм, мВ, кВ) или без (тогда базовая единица: А, В, Ом). Проверка с допуском ±5% по умолчанию, Задание может задать свой допуск. После неверного ответа показывается пошаговое решение; после верного — подтверждающий Разбор.

**Blocked by:** 01 (экран Вопроса и домен-шов проверки)

**Status:** done

- [x] «0,01» и «10мА» распознаются как одинаковый ответ
- [x] Отсутствие суффикса трактуется как базовая единица (А, В, Ом)
- [x] Неверный ввод (мусор, неизвестный суффикс) отклоняется с понятным сообщением, попытка не сжигается
- [x] Юнит-тесты парсера: суффиксы, разделители, допуск, границы диапазона
- [x] Неверный ответ → пошаговое решение показано; верный → подтверждающий Разбор
- [x] Компонентный тест: ввод числа → вердикт → решение

## Comments

Implemented in commits 07edebc + d62c8f4 (TDD, then code-review fixes). Layout:

- `src/domain/quantity.ts` — числовой парсер `parseQuantity(строка, единица)`: значение в базовой единице или сообщение об ошибке. Суффиксы по величинам (мА/А; мВ/В/кВ; Ом/кОм/МОм), регистр значим (м — милли, М — мега). Здесь же `formatQuantity` (0.0095 А → «9,5 мА») для читаемого показа диапазона в вердикте и вся лексика единиц (`unitSuffixes`, `unitNoun`).
- `src/domain/task.ts` — `NumericQuestion` (unit, expectedValue в базовой единице, tolerance? — относительная доля, 0.05 = ±5%) и объединение `Task`.
- `src/domain/evaluate.ts` — `evaluate` стал диспетчером по виду Задания: Ответы и Вердикты несут поле `kind`, несовпадение видов — ошибка контракта. Числовой вердикт: исход, ответ в базовой единице, границы принятого диапазона (включительно), эффективный допуск, Разбор и решение. Помощник `evaluationOfKind` — единственное место сужения вида вердикта.
- `src/components/NumericQuestionScreen.tsx` — тонкий слой: ввод разбирается парсером до вызова `evaluate`, поэтому неверный ввод не сжигает попытку; вердикт показывает «ваш ответ понят как 10 мА» и принятый диапазон. Общий `<Verdict>` — в `Verdict.tsx`, используют оба экрана Вопроса.
- `src/App.tsx` — последовательность демо-Заданий (`demoTasks`): выбор → число → финал. Это минимальная проводка, чтобы второй вид Вопроса был достижим в приложении; настоящий Курс — тикет 03.
- Тесты: 15 — парсер (суффиксы, разделители, регистр, мусор, чужая величина), 12 — evaluate (границы ±5% включительно, переопределение допуска, допуск 0, Разбор/решение, контракт видов), 8 — компонентные потоки. Домен в компонентных тестах не мокается.

Проверено вручную: dev-сервер (примечание: Vite биндится на `localhost`/IPv6 — `127.0.0.1` не отвечает), весь поток в браузере, включая отклонение «10кг», «Верно»/«Неверно», решение и финальный экран; typecheck, полный набор тестов (35) и production-build зелёные.
