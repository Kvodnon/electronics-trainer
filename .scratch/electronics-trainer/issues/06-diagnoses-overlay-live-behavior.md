# 06: Диагнозы, подсветка ошибок, оверлей токов, живое поведение

**What to build:** Полноценная обратная связь по Схема-заданию: после «Проверить» — Диагноз с указанием места ошибки (короткое замыкание, обрыв, обратное включение источника, превышение тока, «работает, но не по условию»), проблемное место подсвечивается прямо на схеме. ## Comments

Implemented in commits 5132d71 + 5ef53d1 (TDD на шве `evaluate`, затем правки по code-review; 167 тестов). Layout:

- `src/domain/circuitDiagnoses.ts` — классификатор Диагнозов по вычисленному решению и проваленным условиям (ADR-0001, не по эталону). `diagnoseCircuit(Холст, решение, проверки)` возвращает один первичный Диагноз: при выполненных условиях — пусто; иначе цепочка приоритетов КЗ → обратное включение → обрыв → превышение тока → «работает, но не по условию». Пороги поведенческие: КЗ — ток ≥ 0,5 А при напряжении зажимов ≤ 20 % ЭДС (учебные токи — миллиамперы); обратное включение — ток против ЭДС (батарею «заряжает» другой источник: ловушка «3 В навстречу 9 В»); обрыв — тока нигде нет, место ищется каскадом «разомкнутый контакт под полным напряжением → Компонент со свободным выводом (нагрузки раньше батареи) → батарея → нет источника (подсветки нет)»; превышение тока — проваленное условие «ток через…» выше верхней границы. Каждый Диагноз несёт `spot` (Компонент **или Провод**) и Разбор с числами расчёта: КЗ с прямой перемычкой между полюсами подсвечивает Провод-виновник, замыкание цепочкой — батарею.
- `src/domain/evaluate.ts` — `CircuitTaskEvaluation.outcome` стал трёхзначным (`CircuitOutcome`): `correct` / `works-not-per-task` / `incorrect` — по виду первичного Диагноза; вердикт получил `diagnoses`. «Работает, но не по условию» в Прогрессе по-прежнему не засчитывается (ModuleScreen проверяет `=== 'correct'`).
- `src/domain/circuitConditions.ts` — `ConditionCheck` получил `componentId`/`measured` (Компонент, на показании которого построена строка Разбора): по ним Диагноз указывает место ошибки. Русские формы имён Компонентов вынесены в `src/domain/componentLexis.ts` (нужны и условиям, и Диагнозам).
- `src/domain/simulator.ts` — `wireCurrents`: ток Провода восстанавливается по ветви Компонента на его конце (знак — вдоль направления Провода from→to); честно только при единственном Проводе на каждом выводе — параллельные Провода дают `null` (ток между ними моделью не определяется). `lampBrightness`: 0 ниже порога накала, дальше линейно до насыщения при `LAMP_FULL_POWER` = 0,5 Вт. `readingsByComponent`, `pinKey` (общий ключ вывода для Симулятора, Диагнозов и оверлея).
- `src/components/canvas/CanvasSymbols.tsx` — живое поведение в символах: лампочка получает ореол (`symbol-lamp-glow`, жёлтый blur) с прозрачностью = яркости от мощности; ротор моторчика обёрнут в группу, крутится CSS-анимацией при мощности выше порога (локальный центр (0,0), `prefers-reduced-motion` уважается).
- `src/components/canvas/CanvasEditor.tsx` — три новых опциональных слоя: `liveReadings` (классы символов), `overlay` (подписи токов на Проводах — в середине маршрута, ток+напряжение под Компонентами), `faultSpot` (пульсирующее кольцо `fault-ring` на Компоненте, бегущий красный пунктир на Проводе).
- `src/components/canvas/CircuitTaskScreen.tsx` — живое решение считается `useMemo` на каждое изменение Холста (лампочка загорается сразу при замыкании контура, ещё до «Проверить»; сбой решения деградирует в «нет показаний»); вердикт трёхсловный: «Пройдено» / «Работает, но не по условию» (янтарный) / «Не пройдено»; под вердиктом — Диагноз с местом ошибки; чекбокс «Токи и напряжения» в панели активен после первой проверки, оверлей строится по замороженному решению вердикта и снимается при правке схемы (вместе с вердиктом и подсветкой).
- Тесты: домен-шов — 10 схем-ловушек через `evaluate` (все пять видов Диагноза: вид, место, текст; трёхзначный исход; «пройдено» без Диагноза); 3 теста `wireCurrents` (последовательная цепь, все Проводы равны контуру, параллельные Провода → null), яркость (порог/рост/насыщение); компонентные — ловушка-обрыв (Диагноз + кольцо на лампочке), перемычка-КЗ (Подсветка Провода `wire-fault`), «работает, но не по условию» (отдельное слово вердикта, не «Пройдено» и не «Не пройдено»), оверлей вкл/выкл со значениями из расчёта (74,9 мА на Проводах, 8,99 В), живое свечение/вращение до «Проверить». Существенный тест `evaluate` переведён на новый смысл: живая схема вне границ → `works-not-per-task`, а `incorrect` ловят ловушки.

Проверено вручную в браузере (IAB): сборка цепи батарея–выключатель–лампочка; ловушка «разомкнутый выключатель» → «Не пройдено» + «Обрыв цепи… контакт разомкнут» + кольцо на выключателе; замыкание контакта — лампочка загорается мгновенно (opacity 1), устаревший вердикт снимается; повторная проверка → «Пройдено»; оверлей — «74,9 мА» на всех трёх Проводах, под Компонентами ток+напряжение (на замкнутом выключателе честные 74,9 мкВ). Вычисленные стили оверлея и ореола подтверждены; скриншоты IAB снова с артефактами захвата (как в тикетах 03/04) — визуальная картина проверена по DOM/стилям. Замечание автоматизации: клики `evaluate` по Палитре по `textContent` не находят «Батарею» — в символе батареи есть текст «+» («+Батарея»); искать по `.palette-item-name`.

Решения по итогам code-review:

- КЗ с прямой перемычкой подсвечивает Провод-виновник, а не «жертву»-батарею; замыкание цепочкой Проводов — батарею (виновника конкретного нет).
- Дубли типа места ошибки убраны: CanvasEditor использует доменный `CircuitDiagnosisSpot`; ключи выводов — общий `pinKey`; сборка карты показаний — `readingsByComponent`.

Заметки для следующих тикетов:

- Напряжение на Проводах в оверлей сознательно не выносится: Провод — узел Симулятора, падения на нём нет; на Проводах — ток, на Компонентах — ток и напряжение.
- Знак тока в оверлее Проводов — вдоль направления Провода from→to; на Компонентах показываются модули (условия тоже проверяют модули — ориентация символа не наказывается).
- «Работает, но не по условию» — зонтичный исход для живой схемы без фундаментальной ошибки: слабый ток, лишний Компонент, напряжение вне границ. Расширять список фундаментальных Диагнозов (М2: диод наоборот, светодиод без резистора) удобно в цепочке приоритетов `diagnoseCircuit` перед `findOvercurrent`.
- Подсветка места ошибки и оверлей — слои CanvasEditor с пропсами; Песочнице (тикет 10) достаточно передать те же пропсы из своего решения.
