# 08: Мультиметр

**What to build:** Режим измерений на Холсте: ученик включает Мультиметр, выбирает режим (напряжение или ток), прикладывает щупы к двум точкам схемы — видит напряжение между ними; измеряет ток выбранной ветви. Мультиметр доступен как свободный инструмент в любом Схема-задании, показания обновляются при любом изменении схемы.

**Blocked by:** 05 (Симулятор как источник показаний)

**Status:** done

- [x] Щупы, приложенные к двум точкам, показывают напряжение между ними, совпадающее с расчётом Симулятора (тест)
- [x] Ток ветви измеряется корректно, включая ветви после переключения выключателя
- [x] Показания обновляются при изменении схемы без перезапуска режима
- [x] Показания недоступны/обнуляются, пока цепь не решается (обрыв — честное «нет тока»)
- [x] Компонентный тест: включить Мультиметр → приложить щупы → показание видно

## Comments

Implemented in commits feat (TDD: узлы выводов → измерения домена → UI-шов) + refactor (правки по code-review; 202 теста). Layout:

- `src/domain/simulator.ts` — `DcSolution` получил `pinNodes`: узел каждого вывода (ключ `pinKey`) — потенциал в вольтах относительно земли своего острова и имя острова (предвидено заметкой тикета 05). Острова без батареи честно дают 0 В, разные острова — разные имена.
- `src/domain/multimeter.ts` — шов Мультиметра, чистый TypeScript: `measureVoltage(решение, красный, чёрный)` — разность потенциалов, знаковая (перестановка щупов меняет знак; щупы разных островов — null: общей цепи нет); `measureCurrent(решение, компонент)` — модуль ветвевого тока (знак ветви — артефакт ориентации символа, как в оверлее и условиях, ориентация не наказывается; у амперметра здесь нет выбранной учеником полярности); `measure(решение, режим, щупы)` — шов экрана с трёхзначным итогом `idle` (щупы не приложены) / `unavailable` (приложены, но общей цепи нет, Компонент удалён или решение не сошлось) / `ok`; `probePoints` — точки приложения щупов для отрисовки; `MultimeterProbes` + `emptyProbes`. Обрыв не ломает измерений: разомкнутый контакт — 1 ГОм, на разрыве честно падает вся ЭДС, ток после отсечки числовой пыли — ровно 0.
- `src/components/canvas/CircuitTaskScreen.tsx` — живое решение поднято в `liveSolution` (сбой решателя → null), из него и живое поведение, и Мультиметр: показание — `useMemo` по `measure`, пересчитывается на каждое изменение Холста без перезапуска режима. В панели Задания: чекбокс «Мультиметр», при включении — выбор режима «Напряжение/Ток» и табло (`output`, aria-live): значение через `formatQuantity` со знаком (напряжение) или «—»; «—» с затемнением и подсказкой «Между щупами нет общей цепи» — только для честного `unavailable`. Включение и смена режима снимают щупы.
- `src/components/canvas/CanvasEditor.tsx` — режим измерений модален: при включённом Мультиметре клик по выводу прикладывает щуп (напряжение: красный, затем чёрный, дальше по кругу; ток: щупы на ветвь Компонента этого вывода), клик по Компоненту без сдвига кладёт щупы на его ветвь (в режиме тока; выделение и панель правки остаются — выключатель замыкается, не выключая Мультиметр), перетаскивание Компонента по-прежнему двигает его. Esc и клик по полю снимают щупы. Щупы рисуются кольцами (`multimeter-probe-red/black`, pointer-events: none) на точках из `probePoints` — в режиме тока на обоих концах ветви. Подсказка в панели инструментов своя для каждого режима.
- CSS: тумблер, выбор режима и «табло» (тёмный фон, фосфорный акцент, моноширинный) в стилистике панели; цвета щупов — свои переменные `--probe-red`/`--probe-black` (красный щуп не «ошибка»).

Тесты (202, было 167+15 тикета 07): домен — 2 на `pinNodes` (выводы за Проводом — один узел, все выводы имеют узел, несоединённые Компоненты — разные острова), 11 золотых Мультиметра (делитель: 6 В между серединой и землёй — совпадение с расчётом; щупы в одной точке — 0 В; перестановка — знак; обрыв — вся ЭДС на разомкнутом контакте; отдельная батарея — ЭДС на зажимах; разные острова и чужой Компонент — null; ток контура 74,9 мА; размыкание — ровно 0 А; ток — модуль при обратной сборке), 3 на шов `measure`/`probePoints` (лестница idle → unavailable → ok в обоих режимах; точки щупов). Компонентные — 6: включить → щупы к двум точкам → «8,99 В» (критерий 5); Esc снимает щупы, перестановка даёт «−8,99 В»; ток ветви «74,9 мА» → размыкание «0 А» → замыкание «74,9 мА» без перезапуска режима (критерии 2–3); щупы без общей цепи — «—»; при включённом Мультиметре клик по выводу прикладывает щуп, а не тянет Провод, после выключения Холст редактируется как прежде; кольца щупов на Холсте в обоих режимах.

Code-review (Standards + Spec): нарушений документированных стандартов нет; исправлено по замечаниям — тройка щупов собрана в доменный тип `MultimeterProbes` с `emptyProbes` (Data Clump и дубли литерала), режимные ветви сведены в доменный шов `measure` с трёхзначным итогом и `probePoints` (Repeated Switches и презентационная логика из компонента), `tone` → `color`, `--probe-red`/`--probe-black` вместо заимствованного `--incorrect`, guard в `endDrag` упрощён. Оставлено осознанно: модальность «щупы вместо Проводов» при включённом Мультиметре (в режиме напряжения схема правится кликами по Компонентам и панелью, Проводы — после выключения; падение компонента из Палитры работает всегда), знак напряжения знаковый, а ток — модуль (полярность амперметра не выбирается учеником), «0 В» на мёртвом острове — честная физика (критерий допускает «обнуляются»).

Проверено вручную в браузере (IAB, vite dev): М1 засеяна пройденной → М2: Теория → Вопрос → Схема-задание; собран контур батарея–выключатель–лампочка (3 Провода), выключатель замкнут, лампочка горит (ореол opacity 1); «Мультиметр» → щупы на «плюс» батареи и землю → табло «8,99 В», кольца щупов на точках; Esc → «—»; режим «Ток» → клик по выключателю → «74,9 мА»; размыкание галочкой прямо в панели правки → «0 А» и лампочка гаснет, замыкание → «74,9 мА» — режим не перезапускался.
