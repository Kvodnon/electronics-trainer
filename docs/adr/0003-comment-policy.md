# Комментарии несут только невыводимое знание

Идея «удалить все комментарии — код самодокументируется, а есть спека» была проверена аудитом кодовой базы и не подтвердилась: в не-тестовых исходниках пересказов кода почти нет — комментарии несут физику реализации (компаньонная модель конденсатора Δt/2C, правила переключения состояний транзистора, семантика выводов символов по ГОСТ 2.728/2.743/2.755), инварианты контрактов и воркараунды, которых в `docs/spec.md` нет — спека описывает продукт, а не строчки реализации. Решено: комментарий любого вида обязан говорить то, что нельзя вывести из кода, — «почему», контракт, физику, ссылку на стандарт, воркараунд; пересказ идентификатора удаляется. Doc-блоки `/** */` живут на модульных шапках и на экспортах; на внутренних сущностях — только если несут такой смысл сверх сигнатуры.

## Considered Options

- Ноль комментариев — отвергнуто: перечисленное знание существует только в комментариях и было бы утрачено безвозвратно.
- Оставить как есть — отвергнуто: шум существовал и вычищен — 125 строк нарратива в тестах («собираем контур…») и 27 баннеров-секций в CSS.

## Consequences

- В тестах сценарий описывается строками `describe`/`it`; остаются расчётные раскладки («9 В / 120,1 Ом = 74,9 мА») и why-пояснения техник тестирования.
- В CSS остаются пояснения визуальной семантики (что и почему рисуется), баннеры-секции — нет.
- Линтера на комментарии нет: политика держится на этом ADR и ревью.
